# 2026-09-27: LogId channel one-of member removed: reserved variant never implemented; swarmy is currently its own only client.
PUT /v1/events/{connection_id}/subscription removed `subschema #2` from the `cursors/items/log_id` request property `oneOf` list

# 2026-09-27: The session header adopted a versioned current format. Earlier
# migration guidance was superseded by the 2026-09-29 store reset below.

# 2026-09-27: A non-idle session alone returns session_not_idle; unrelated state failures now return storage_error instead of session_not_idle. Active agent placement returns an actionable conflict.
POST /v1/sessions/{id}/messages changes invalid state error code from session_not_idle to storage_error except when session is not idle
PATCH /v1/cli/agents/{name}/settings changes active placement error code from storage_error to agent_computer_placed
PATCH /v1/agents/{id} changes active placement error code from storage_error to agent_computer_placed

# 2026-09-27: Inference failure events append a typed failure_kind, while old stored events decode with unknown. Update event readers before writers.
GET /v1/sessions/{id}/events adds inference_failed/failure_kind to response events

# 2026-09-27: Store errors now report facts rather than CLI commands.
DELETE /v1/sessions/{id} changes main_session_close error message to omit CLI advice

# 2026-09-27: Worker system notices now carry typed kind markers while keeping their text; old event readers must be upgraded first.
GET /v1/sessions/{id}/events adds notice part kind to message parts

# 2026-09-27: Encrypted credential records append typed bookkeeping. Earlier
# migration guidance was superseded by the 2026-09-29 store reset below.
POST /v1/cli/credentials adds optional record/bookkeeping to the request payload

# 2026-09-27: InferenceFailed failure_kind, Part::Notice in events and snapshots, and typed credential bookkeeping fields are one-way stored format changes. Older binaries cannot read rows written after this upgrade. Upgrade the entire swarm together; do not roll back.
# 2026-09-27: MissingInferenceWait is not a session-not-idle error. Interrupt now reports the storage fallback instead of an unrelated conflict code.
POST /v1/sessions/{id}/interrupt changes MissingInferenceWait error code from session_not_idle (409) to storage_error (500)

# 2026-09-28: Summary inference jobs append trailing summary and split-prefix flags for explicit job identity; request cache policy is transient and does not change the stored layout. The delivery reference appends the same flags. Successor openings are user-role Markdown rather than system-role JSON; old system openings still read. Upgrade workers and gateways together; older binaries cannot read new job encodings.
GET /v1/sessions/{id}/events changes successor opening from system JSON to user Markdown
# 2026-09-28: Obsolete context warning notices retain their binary discriminant but render as legacy_context_notice in old event JSON; no new warning is emitted.
GET /v1/sessions/{id}/events changes legacy notice kind text to legacy_context_notice
# 2026-09-28: Checkpoint jobs append a trailing cut and recovery marker, so a resumed worker archives the same head it summarized. Older jobs decode with absent markers; older binaries cannot decode the appended fields.

# 2026-09-28: Workers distinguish provider context overflow from other failures for one compact-and-retry attempt. Older stored failures decode as unknown; older binaries cannot decode the appended enum variant. Upgrade workers and gateways together.
GET /v1/sessions/{id}/events adds context_overflow to inference_failed/failure_kind values
# 2026-09-28: Queued user messages add a new trailing event discriminant carrying the original enqueue time. Upgrade event readers before accepting queued input.
POST /v1/sessions/{id}/messages accepts queue=true without interrupting a busy turn; GET /v1/sessions/{id}/events adds message_queued records at delivery

# 2026-09-29: One-way development store reset. Wipe the development store before deploying:
# - Retired single-record credential rows and credential leases no longer migrate or appear in doctor. String bookkeeping flags in encrypted entry rows no longer convert on read or write.
# - Session V1 headers no longer decode or migrate. The session kind, plan, inference, interrupt, route, route-step, image, idle, and state-since side-row key families are removed.
# - Capped turn metric V1 envelopes and bare rows no longer decode or migrate. Bare inference and tool detail rows are not accepted; only the current summary and detail envelopes remain.
# - Pre-current agent postcard layouts (without main session, settings, provider, requirements, or route) no longer decode.
# - Pre-index raw usage pruning markers and unindexed usage records are no longer maintained. Older five-field TokenUsage rows and truncated current rows no longer decode.
# - Volumes without retained snapshot rows no longer import a parent chain; missing metadata reports corruption. Placements require hosting metadata, and idle sessions require an idle timestamp.
# - Gateway advertisements without a reason no longer decode. Legacy context notice kinds no longer decode.
# - Deprecated flat remote AWS settings and slash-separated S3 bucket/prefix settings are rejected. Saved remote state requires launch_attempted instead of defaulting it.
GET /v1/cli/doctor removed the optional property `legacy_credential_rows` from the response with the `200` status
GET /v1/sessions/{id}/events removes legacy_context_notice from notice kind values
# 2026-09-29: Stored event rows no longer decode the unmetered completion variant or missing failure-kind and route-attribution fields. Current event discriminants after the removed completion shift by one. TokenUsage now requires six fields; five-field usage rows are rejected. Wipe the development store before deployment.
# 2026-09-29: Turn metric envelopes use the current summary (tag 0), inference (tag 1), and tool (tag 2) variants only; older capped-metrics tags and bare detail rows are rejected.
# 2026-09-29: Remove stream event variants that had no producer. Clients cannot receive them.
GET /v1/events removes turn_started, turn_finished, inference_error, service_status_changed, and node_status_changed payload variants

# 2026-09-29: Provider availability and credential placeholders removed. The
# provider list carries the typed wire protocol (`api`), auth kinds, and
# environment keys; the old `api`/`credential` strings lived in the flattened
# catalog map whose removal is recorded above. Availability is a doctor
# concern and credentials are listed under /v1/credentials.
GET /v1/providers removed the required property `items/status` from the response with the `200` status
# 2026-09-29: One image header shape everywhere. The build response embedded
# the stored manifest, leaking the root hash as a 32-number array, while
# `image show` printed hex. Both now share the typed `ImageHeader` with a
# hex root hash; the CLI is the only reader and was updated in lockstep.
POST /v1/images/uploads changes header/root_hash from an array to a hex string
# 2026-09-29: The image manifest id is `manifest_id` everywhere, matching the
# build event. Readers of `id` on image show and ls switch to `manifest_id`.
GET /v1/images removed the required property `items/id` from the response with the `200` status
GET /v1/images/{name}/{tag} removed the required property `id` from the response with the `200` status

# 2026-09-29: Session archived flag removed. Readers derive it from next_session being present; the field duplicated the successor link.
GET /v1/sessions removes archived from response properties
GET /v1/sessions/{id} removes archived from response properties

# Operator steps (do not run `swarmy dev up` first: dev.rs reads the old file
# and fails; `swarmy remote upgrade` only swaps binaries and never migrates):
# - Laptop: for each config file (project `.swarmy/config.toml` and user
#   `~/.swarmy/config.toml` or `$XDG_CONFIG_HOME/swarmy/config.toml`), run
#   `python3 scripts/migrate-config-2026-09.py <file>` (writes `<file>.bak`,
#   idempotent, reports unknown keys without dropping them), verify with
#   `cargo run -p swarmy-config --example check-config <file>`, then run
#   `swarmy dev up`.
# - Each node: copy the script (it needs only stdlib tomllib) and run
#   `python3 migrate-config-2026-09.py /home/ubuntu/swarmy/.swarmy/config.toml`
#   over SSH, verify, then restart services (`swarmy remote upgrade` or
#   `sudo systemctl restart swarmy-*`). Fresh nodes provisioned after this
